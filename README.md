# Граф денег — объяснимый анализ транзакционной сети

Локальный прототип для кейса HackAlem AI от Freedom. Строит ориентированный взвешенный граф переводов, назначает каждому узлу объяснимую основную роль, рассчитывает приоритет ручной проверки, кластеризует граф и создаёт три CSV и автономную HTML-схему.

Все оценки — эвристические гипотезы по обезличенным данным, не утверждения о виновности и не замена расследованию. Во время работы используются только файлы датасета; сетевые API и клиентские персональные данные не нужны.

## Запуск

Требуются Python 3.10+ и зависимости из `starter/requirements.txt`.

Из корня проекта:

```powershell
python -m pip install -r starter/requirements.txt
python starter/starter.py --data data --out out
```

Архивы исходных данных и starter нужно распаковать так, чтобы в `data/` лежали три Parquet-файла. Архив `starter (1).zip` не содержит данные. После запуска в `out/` появляются:

- `nodes_roles.csv` — одна запись на узел;
- `clusters.csv` — агрегаты и осторожная структурная гипотеза на сообщество;
- `top_nodes.csv` — первые 50 узлов для проверки;
- `index.html` — автономный экран графа, созданный вместе с CSV.
- `node_features.csv` — признаки клиентов и вклады в приоритет;
- `analysis.json` — данные для бэкенда с точными строковыми ID.

Схема `architecture.svg` находится в корне, а не генерируется в `out/`.

Откройте `out/index.html` в браузере. В интерфейсе доступны поиск `gid`, фильтр по роли и кластеру, карточка узла, масштабирование и перемещение графа. У жёлтого узла указана граница обхода на глубине 4.

## Что делает пайплайн

1. Загружает `edges.parquet`, `nodes.parquet` и `transactions.parquet`, проверяет схему, уникальность рёбер, соответствие транзакционных пар, сумм и количества переводов, а также наличие узлов для рёбер.
2. Создаёт направленный взвешенный граф, сохраняя изолированные узлы из `nodes.parquet`.
3. Рассчитывает степени и обороты узлов, PageRank, HITS, охват от начальных seed-клиентов и долю суммы, которую можно сопоставить с поступлениями за предыдущие 0–2 дня.
4. На неориентированной взвешенной проекции запускает Louvain с фиксированным seed. Изолированные узлы остаются отдельными сообществами.
5. Применяет формальные правила основной роли и объяснимый приоритет, формирует CSV и страницу просмотра.

## Правила ролей

Правила применяются сверху вниз; первая сработавшая определяет основную роль. Пороги эвристические и доступны для пересмотра командой в `starter/starter.py`.

| Роль | Правило |
|---|---|
| `coordinator` | Не-seed узел имеет не менее двух достижимых seed-предков, не менее двух разных входящих и двух исходящих соседей. Это структурная гипотеза о связующем узле. |
| `consolidator` | Не-seed узел получает от 3+ разных узлов и имеет хотя бы одного исходящего получателя. |
| `distributor` | Имеет 5+ разных исходящих получателей. |
| `transit` | Не-seed с входящими и исходящими связями, у которого доля исходящего/входящего оборота находится в пределах 0.70–1.30 **или** не менее 35% исходящей суммы можно сопоставить с поступлениями в предыдущие 0–2 дня. |
| `terminal` | Имеет входящие связи, не имеет исходящих и не является узлом, обрезанным на глубине 4. Это признак только внутри наблюдаемой выборки. |
| `peripheral` | Не соответствует указанным выше правилам либо имеет недостаточно данных. Узел четвёртого колена без исходящих остаётся здесь с явным предупреждением о границе обхода. |

`role_score` — сила соответствия выбранной эвристике, ограниченная диапазоном 0–1; это не калиброванная вероятность. `evidence` содержит конкретные метрики, использованные для решения. Для seed-узлов входящие суммы и `pass_through` не используются как надёжная оценка баланса: входящие переводы из-за пределов графа отсутствуют.

## Приоритет и кластеры

`priority_score` — взвешенный процентильный рейтинг по входящей степени, исходящей степени, HITS authority, HITS hub, PageRank и числу достижимых seed-предков. Весовые коэффициенты: 0.18, 0.18, 0.20, 0.16, 0.16 и 0.12 соответственно. Узлы, обрезанные на четвёртом колене, получают понижающий множитель 0.75. Рейтинг предлагает порядок ручной проверки и не означает подозрение или вину.

Кластеризация Louvain рассчитывается на неориентированной проекции, где встречные и односторонние переводы образуют общую связь, а встречные веса суммируются. В `clusters.csv` внутренний оборот считается по направленным рёбрам исходного графа. Текст гипотезы выводится по числу seed и соотношению видимых входящих и исходящих сумм, с оговоркой о неполноте выборки.

В `top_nodes.csv` выводятся 50 верхних узлов (или все узлы, если их меньше) в порядке `priority_score`. Обоснование включает роль, три главных числовых вклада в рейтинг, множитель и итог. Полные вклады доступны в node_features.csv и analysis.json. Изолированные клиенты получают приоритет 0.

## Проверка сценария

После запуска проверьте, что:

- `nodes_roles.csv` содержит число строк, равное числу уникальных `gid` в `nodes.parquet`;
- все обязательные поля заполнены, роли принадлежат словарю, значения оценок находятся в пределах 0–1;
- у каждого узла есть `cluster_id`, включая изолированные узлы;
- `clusters.csv` содержит строку на кластер, а `top_nodes.csv` — не менее 20 строк для данного датасета;
- у узлов `depth=4` без исходящих связей не выставлена роль `terminal` только по факту отсутствия исходящих;
- HTML открывается локально и поиск по `gid` показывает карточку узла;
- README-команду запуска можно повторить из чистого окружения с установленными зависимостями.

Контрольный запуск и повторный пересчёт займут до 5 минут на обычном ноутбуке согласно ограничению кейса. Полный объём метрик намеренно ограничен линейным обходом рёбер, PageRank/HITS и Louvain; тяжёлый точный betweenness для всех узлов не используется.

## Результат на приложенном наборе

Пайплайн сформировал 2 248 уникальных записей без пустых обязательных полей, 91 кластер и 50 строк top-list. Ровно 8 получившихся сообществ содержат больше одного seed — такой же структурный ориентир указан в примечании организаторов к ТЗ. На этом наборе роли распределились так: 1 079 `terminal`, 752 `peripheral`, 157 `coordinator`, 162 `transit`, 55 `distributor` и 43 `consolidator`. Ни один `seed` и ни один узел, помеченный как обрезанный на глубине 4, не классифицирован как `terminal`. Замеренный запуск на этой среде — 3.38 секунды (новый контрольный запуск; bundled Python, fastparquet); время зависит от оборудования и версий библиотек.

## Сценарий пятиминутного демо

1. Запустить команду из раздела «Запуск» и показать, что создаются все CSV и `index.html`.
2. В HTML найти `gid` из топ-листа; показать его роль, числовое объяснение, соседей, суммы и кластер.
3. Переключить фильтр роли или кластера и показать направленные связи.
4. Найти узел на глубине 4 и объяснить, почему он не объявляется доказанным конечным получателем.
5. Открыть `top_nodes.csv` и `clusters.csv`, пояснить формулу приоритета и оговорку, что это порядок аналитической проверки, а не вывод о виновности.

В презентации стоит явно сказать: роли не имеют ground truth в наборе; пороги являются интерпретируемыми эвристиками, а входящие потоки и граница обхода делают часть выводов неполными. Проект разрабатывался с AI-агентом; сам аналитический результат намеренно детерминирован и воспроизводим без LLM/API.

## Ограничения и масштабирование

- Данные содержат только исходящие переводы, суммы ниже 5 000 ₸ отфильтрованы, атрибутов клиентов и ground truth ролей нет.
- Четвёртая глубина обхода обрезает будущие исходящие связи; алгоритм помечает такие наблюдения как неполные, но не может восстановить отсутствующие данные.
- `pass_through` — отношение сумм внутри графа, не банковский баланс.
- Кластеры Louvain строятся на неориентированной проекции; направление сохраняется в CSV и визуализации потоков.
- Правила и пороги объяснимы, но эвристичны. Для эксплуатации их нужно откалибровать на проверенных аналитиком примерах и проверять качество/смещение.
- До примерно миллиона узлов следует заменить объектный NetworkX-граф на разреженные CSR/CSC-матрицы или графовый движок, считать PageRank/HITS пакетно, хранить рёбра в колоночном формате и не отдавать браузеру весь граф сразу: загружать подграф по кластеру/поиску и агрегировать дальние связи. Контракт CSV и смысл объяснений можно сохранить.
