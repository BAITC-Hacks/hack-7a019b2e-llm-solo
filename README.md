## Граф денег

Решение кейса HackAlem AI «Граф денег: восстановление финансовой структуры
организованной группы по транзакционной сети». Инструмент строит направленный
взвешенный граф, объяснимо назначает роль каждому узлу, группирует сеть и
формирует список узлов для первоочередной проверки AML-аналитиком.

### Быстрый запуск

Требования: Python 3.10+, зависимости из `requirements.txt`.

```bash
pip install -r requirements.txt
python pipeline.py --data ./data --out ./out
```

На выходе:

- `out/nodes_roles.csv` — 2248 узлов, роль, уверенность, кластер, приоритет и числовое обоснование;
- `out/clusters.csv` — сообщества, оборот внутри, seed-узлы и гипотеза назначения;
- `out/top_nodes.csv` — ранжированный список узлов для проверки;
- `out/network.html` — локальная визуализация направлений потоков и ролей.

### Frontend

Есть отдельный статический dashboard в `frontend/`. После запуска пайплайна его
можно открыть локально так:

```bash
python -m http.server 8000
# открыть http://localhost:8000/frontend/
```

Dashboard автоматически загружает `out/graph.json`. Также его можно загрузить
через кнопку `Загрузить graph.json`. В интерфейсе доступны обзор KPI, поиск по
`gid`, фильтры роли и кластера, направленный граф, карточка узла, top-лист и
кластерный обзор. Это отдельный слой представления: backend может позже отдавать
тот же JSON через API.

### Критерии ролей

Пороговые значения вычисляются по квантилям текущего датасета, поэтому результат
не зашит под конкретные `gid`.

- `consolidator` — получает от нескольких контрагентов и удерживает заметную часть входящего оборота;
- `transit` — имеет вход и выход, а `pass_through` близок к 1;
- `distributor` — имеет веерную рассылку на большое число получателей;
- `terminal` — имеет входящие переводы, но нет исходящих до глубины 4;
- `coordinator` — сочетает высокий PageRank, посредничество и hub-score;
- `peripheral` — выраженных признаков остальных ролей нет.

Узлы `depth=4` без исходящих не объявляются автоматически конечными: это может
быть артефакт обрыва обхода. Для seed-узлов не используется наивное отношение
«отдал / получил», поскольку входящие потоки до начала выборки неизвестны.

### Ограничения

Данные обезличены и содержат только структуру, суммы и даты внутри банка.
Формулировки — гипотезы для проверки, а не утверждения о виновности. Для графа
порядка миллиона узлов следует заменить точное betweenness на приближённое,
перейти на потоковую агрегацию и специализированное хранение графа.
