# Передача Python-бэкенда перед сдачей

Проверено 23.09.2026. Обязательная серверная часть кейса — локальный Python-пайплайн. Динамический API, Go, SQL-БД и LLM не используются. Исходники фронтенда в этой доработке не изменялись; формат `schema_version=1` сохранён.

## Запуск и приёмка

После установки Python 3.11/3.12 и `requirements.txt`, из корня:

```powershell
.\.venv\Scripts\python.exe -m moneygraph --data data --out artifacts
.\.venv\Scripts\python.exe -m moneygraph.verify --data data --out artifacts
```

Первый запуск создаёт все результаты. Второй ничего не записывает: проверяет их по исходным Parquet и возвращает `status: "ok"`/exit 0 либо ошибку/exit 1. Для собственного конфига обоим запускам передайте одинаковый `--config`.

Для локального просмотра добавьте `--serve` к первой команде. Это раздача готовых файлов с `127.0.0.1:8765`; расчёт не выполняется при открытии каждой карточки. Данные не отправляются наружу.

## Что получает фронтенд

Источник — `artifacts/graph.json`, полная спецификация в [BACKEND_CONTRACT.md](../BACKEND_CONTRACT.md).

| Сценарий | Данные Python |
| --- | --- |
| Сводка | `summary`: размер, период, оборот, роли, ограничения |
| Приоритетные клиенты | `top`: ранги, gid, роли, score, why |
| Карточка любого клиента | `nodes`: все клиенты, метрики, evidence, причины peripheral |
| Связи | `edges`: направленные пары, суммы в KZT/сотых, число переводов, depth |
| Отдельные операции | `transactions`: даты, суммы, src/dst, канонический row_id; повторы сохранены |
| Группы | `clusters` и `nodes.cluster_id`: размеры, seed, внутренний оборот, лидеры, гипотезы |
| Контроль версии | `schema_version`, `rule_version`, `snapshot_id`, хеши CSV |

GID в JSON — строки, даты — `YYYY-MM-DD`. `row_id` не является банковским ID. Нулевые значения отличаются от отсутствующих. Все клиентские индексы/фильтры могут строиться по одному снимку, дополнительный сервер для этого не нужен.

## Что подтверждено

- 44/44 Python-теста, включая 16 новых регрессий входной валидации и проверки записанных экспортов.
- Полный запуск официального набора — 5.761 секунды на этой машине, лимит ТЗ — 300 секунд.
- 2248 узлов, 3119 рёбер, 4840 операций; 81 seed, все 19 изолятов и 444 обрыва сохранены.
- 105 кластеров, 50 строк приоритетов; обязательные поля заполнены, evidence 1–200 символов.
- Три CSV совпадают по SHA256 с предыдущей проверенной версией: финансовые правила и рейтинг этой доработкой не изменены.
- Повторный прогон текущего кода на Python 3.11.9 и 3.12.14 подтвердил побайтовое совпадение трёх CSV и содержательных полей JSON; перестановки входных строк с seed 7 и 91 результата не изменили.
- Полная приёмка исходники → CSV/JSON успешно выполнена. Она обнаруживает удаление повторной операции, искажение длинного gid/суммы, изменение CSV и устаревшие исходники.

Это проверка реализации и воспроизводимости, не измерение accuracy: размеченных истинных ролей нет.

## Где данные и почему нет БД

`data/*.parquet` хранит исходную разовую выгрузку. Python загружает её в pandas/NetworkX и записывает результаты в `artifacts/`. JSON — файл снимка, не база данных. ТЗ прямо говорит, что онлайн-поток не требуется; отдельная БД не входит в обязательные функции. Исходные файлы, JSON, CSV и HTML остаются в разрешённом локальном контуре и не коммитятся.

## Граница готового MVP и сдача

Все пять must-have ТЗ покрыты текущим пайплайном и существующим экраном. Циклы, всплески, анализ повторяющихся сумм, отдельные обзоры компонент и AI-ассистент — дальнейшие улучшения. Они не заявляются реализованными. `coordinator` остаётся гипотезой структурного посредника по документированному правилу, а не доказательством управления группой.

ТЗ §9 разрешает любой язык и библиотеки и рекомендует Python; команда закрепила Python. Это не разрешение отправлять данные в любой сторонний сервис: действуют отдельные правила приватности. Для текущего сценария дополнительные инструменты и кредиты не нужны.

На момент проверки GitHub актуальная рабочая ветка — `Muha`, а `main` содержит только `Initial commit`. Перед сдачей команда должна согласовать финальное объединение веток и убедиться, что жюри запускает актуальный код. Push не завершает сдачу: на платформе отдельно нажмите «Сдать решение», укажите название и описание. Обязательные CSV передайте разрешённым организаторами способом. Сценарий пятиминутного демо и схема уже находятся в README.
