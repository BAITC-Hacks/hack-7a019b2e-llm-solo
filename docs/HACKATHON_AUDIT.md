## Правила участия: что нужно сделать самому

Источник: «Правила зачета участия.pdf», стр. 1–2.

- Быть в зоне до старта; бейдж сканируется при входе. Не передавать его другим.
- После старта не менять место и сектор.
- Выходы — суммарно не больше 60 минут, с уведомлением стюарда и сканированием при выходе/возвращении.
- Последний час находиться в зоне; экстренный выход до 5 минут — только с разрешения стюарда.
- Не уходить до официального завершения, внести личный вклад.
- В документе прямо сказано: «Проект должен быть создан в рамках хакатона». Разрешение на использование заранее написанного каркаса из этой фразы не следует. До старта уточнить у организаторов допустимость заготовок. Не менять даты и не выдавать предварительную работу за сделанную на площадке.

Источник: «Инструкция_для_участников_HackAlem_AI.pdf», стр. 1–2.

- Выбрать один кейс на платформе и распределить обязанности внутри команды.
- Использовать AI-агента; финальный код должен находиться в командном репозитории, выданном платформой.
- После push отдельно нажать «Сдать решение» на странице кейса, заполнить название и описание. Один push не заменяет сдачу.
- README должен описывать фактически реализованные функции, технологии, архитектуру, запуск, проверку, данные/сервисы и ограничения. Deployed-ссылка нужна, только если развёрнутая версия есть.

Регистрация команды подтверждена пользователем. Состав команды, выбор кейса, дедлайн, факт сдачи и физическое присутствие по локальным файлам не подтверждаются.

- Обновить ОС/браузер заранее, перезагрузить, проверить порты, свободное место и вход в необходимые программы.

Источник: инструкция по кибербезопасности, русская часть стр. 1–4; английская часть повторяет положения.

## Как трактовать 14 неуспешных QA-тестов

Исправить в первую очередь при продолжении разработки:

1. `run()` теряет готовый ответ, если подменённая реализация памяти бросает ошибку; memorySaved не гарантированно boolean.
2. Ошибки подключения зависимостей смешаны с невалидным ответом модели.
3. Нет предела на размер HTTP-тела; max_output_tokens ограничивает генерацию, но не размер любого ответа сервера. Тело HTTP-ошибки не отменяется.
4. Пустые env-настройки имеют неожиданное поведение, в том числе в offline-режиме.

Согласовать контракт, затем исправить реализацию и тесты:

- Параллельные append теряют обновления: реальный риск при переходе к веб-серверу, но текущий README честно ограничивает запись одним запросом. Для новой версии нужна очередь/блокировка либо SQLite.
- Одна неверная запись сбрасывает активную историю целиком; резервная копия сохраняется, то есть безвозвратного удаления всего файла не происходит. Лучше восстанавливать валидные записи отдельно.
- Бесконечное накопление резервных копий — ограничение; лимит именно 2 не задан пользователем или ТЗ, это произвольное ожидание QA.
- Тест про дедлайн ждёт invalid_output уже после истечения времени, а mock игнорирует abort. Такой результат спорен: для реального сетевого дедлайна timeout ожидаем. Нужен тест реального транспорта, не подгонка под это ожидание.
- Тест про изменяемую schema после freeze сам бросит TypeError при push; нужно проверять невозможность изменения, а не требовать, чтобы push молча сработал.
- Настраиваемый URL полезен для интеграционных тестов, но Azure/прокси не требуются кейсом. Поддержку Azure нельзя обещать одной заменой URL.
- Синтетический TypeError из fetch и реальный сетевой TypeError не всегда надёжно различимы; сохранить cause для диагностики без утечки секретов.
- Тест лимита памяти через RSS смешивает сервер и клиент в одном процессе; полезнее детерминированный лимит прочитанных байтов и проверка отмены потока.

Не удалять QA-тесты ради зелёного отчёта. Отделить обязательный контракт от новых пожеланий и документировать изменения.

## Проверка предоставленного starter

Архивы находятся в C:/Users/user/Downloads, README датасета — в той же папке. В архивах есть служебные __MACOSX/._*; при распаковке их пропускать.

- Можно использовать загрузку Parquet и расчёт степеней, сумм, числа переводов, PageRank, pass_through и truncated_by_depth.
- starter.py намеренно оставляет роли/evidence пустыми, cluster_id=-1, clusters.csv и top_nodes.csv без строк. Его запуск не закрывает must have.
- sanity_check группирует транзакции, но проверяет только наличие пар src,dst. Суммы и количество переводов фактически не сравнивает, хотя печатает edges == transactions: OK. Добавить отдельные проверки чисел и допустимой погрешности float64.
- build_graph добавляет только концы рёбер. basic_features возвращает всех nodes через merge/map, но сами изоляты отсутствуют в G и потеряются при кластеризации. Добавить G.add_nodes_from(nodes.gid) до рёбер.
- requirements.txt задаёт только нижние границы, не воспроизводимый набор версий. Проверить фактические зависимости PageRank на выбранной версии NetworkX и зафиксировать рабочее окружение.
- README starter прямо разрешает дополнительные колонки CSV. Сохраняем обязательные поля без изменений; вспомогательные признаки можно оставить отдельно для компактности.

Во время аудита появился QA-REPORT.md с отдельным заданием на исправление. Он прочитан как дополнительный материал, исходники и QA-тесты в этом этапе не изменялись. Его требования нельзя автоматически приравнивать к требованиям графового кейса.
