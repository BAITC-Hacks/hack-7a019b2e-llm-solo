# TRACE — фронтенд команды LLM-Solo

Статическое приложение без сборки, CDN и npm-зависимостей.

Исходный интерфейс импортирован из `origin/Zhans` (коммит `bdbbb65`). [Контракт бэкенда](../BACKEND_CONTRACT.md) описывает JSON и ограничения данных.

## Запуск

Сервер приложений не используется: команда отказалась от Go. Данные попадают в интерфейс локальным импортом.

Сначала выполните расчёт, чтобы появился `artifacts/graph.json`:

```powershell
.\.venv\Scripts\python.exe -m moneygraph --data data --out artifacts
```

Затем откройте `frontend/index.html` как файл — либо, если браузер ограничивает локальные файлы, поднимите статическую раздачу из корня репозитория:

```powershell
.\.venv\Scripts\python.exe -m http.server 8000 --bind 127.0.0.1
```

и откройте `http://127.0.0.1:8000/frontend/`. Нажмите «Импорт данных» и выберите `artifacts/graph.json`. Файл читается в браузере и никуда не отправляется. Доступны граф, карточки, связи и экспорт; постраничные операции через API в этом режиме не запрашиваются.

## Структура

- `index.html` — каркас, навигация, фильтры и диалог клиента.
- `styles.css` — тема и адаптивные состояния.
- `DESIGN.md` — визуальная концепция «Аналитическое досье», палитра и правила для новых экранов.
- `app.js` — обзор, SVG-граф, фильтры, таблица, кластеры, импорт/экспорт.
- `data.js` — lossless-парсер GID, валидация, индексы связей, CSV.
- `data.test.cjs` — тесты контракта; запуск `node --test frontend/data.test.cjs` из корня.
- `backend.test.cjs` — регрессии интеграции: ошибки API, точные суммы/даты, нулевые метрики, локальный импорт, смена набора и запоздавшие ответы карточки.
- `package.json` — только граница CommonJS для исходных тестов; зависимостей и сборки нет.

## Контракт для бэкенда

```json
{
  "nodes": [{
    "gid": "100000000000000001",
    "role": "transit",
    "cluster_id": 0,
    "priority_score": 0.65,
    "role_score": 0.8,
    "evidence": "Численное обоснование роли и приоритета",
    "depth": 1,
    "is_seed": false,
    "in_kzt": 100000,
    "out_kzt": 90000,
    "truncated_by_depth": false
  }],
  "edges": []
}
```

Ребро: `{ "src": "...", "dst": "...", "sum_kzt": 90000, "n_tx": 3 }`.
Оба конца должны присутствовать в `nodes`. `gid`, `src`, `dst` передавать **строками**: int64 не помещается в безопасный JavaScript Number. Для совместимости текущий числовой JSON читается как текст lossless-парсером; не заменять это на `response.json()`.

Роли: `coordinator`, `consolidator`, `distributor`, `transit`, `terminal`, `peripheral`.
Скоры в пределах 0–1; в интерфейсе показаны на шкале 0–100. Это оценки алгоритма, не вероятность виновности. Степени узлов вычисляются по уникальным контрагентам без самопереводов. Роли и скоринг фронтенд не пересчитывает. Подписи ролей обозначают гипотезы: например, «Кандидат на транзит» и «Структурный посредник», сохраняя исходный enum в данных и CSV.

## Поведение интерфейса

- Обзор показывает 150 приоритетных узлов, отдельный граф — 180; кнопка позволяет показать всю выборку.
- Точный поиск GID и «Показать связи на графе» раскрывают всех прямых соседей независимо от фильтров. Поиск не ограничен демонстрационными узлами.
- Масштабирование кнопками/колесом, перемещение перетаскиванием; окраска по роли или кластеру.
- Наведение или фокус клавиатуры выделяет прямые переводы узла. Заметка «Начальная точка» открывает окружение самого приоритетного клиента текущей выборки.
- Кластеры считают внутренний оборот только по рёбрам между участниками одной группы.
- Отсутствие исходящих на глубине 4 отмечено как граница данных, а не доказательство конечного получателя.
- Карточка сохраняет численные временные метрики, доли входа/выхода, сопоставленный объём, причины отсутствия роли, все сработавшие правила и вклад в приоритет. Отсутствующая метрика отличается от рассчитанного нуля.
- Суммы в карточке, таблице и отдельных операциях показываются с двумя десятичными знаками. Компактные обзорные показатели могут использовать тысячи/миллионы.
- Для графа из API карточка загружает операции страницами по 100: `/api/nodes/{gid}/transactions?offset=0&limit=100`. Даты показываются как `YYYY-MM-DD`, без вымышленного времени. `row_id` — номер записи в канонической выгрузке, не банковский идентификатор; одинаковые операции сохраняются.
- `snapshot_id` графа сверяется с заголовком `X-Snapshot-ID` страницы операций. При смене набора требуется обновить страницу. Запоздавший ответ для другой карточки или предыдущего набора не меняет текущий экран; запросы ограничены 15 секундами.
- Экспортирует текущий отфильтрованный и отсортированный список (не только страницу), колонки `rank,gid,role,priority_score,why`.
- GID в CSV точный, но Excel может округлить его при автоматическом открытии. Импортируйте колонку GID как текст.
- `Escape` закрывает карточку; `/` переводит фокус в поиск. На узлы графа можно переходить с клавиатуры.

Проверка: `node --test frontend/data.test.cjs frontend/backend.test.cjs`. Сетевые ответы в тестах подменены; данные хакатона и внешние API не нужны. Загрузчик сохраняет цепочку `response.text()` → `MoneyGraph.parse()` → `MoneyGraph.normalize()`.
