# Muha: подключение бэкенда к TRACE

Ветка фронтенда: **Zhans** (с большой Z). На сайте уже есть граф, карточки клиентов и чат «След» с миниатюрным львом. Это готовый клиент, не реализация AI-сервера.

## Что подключить

1. Раздавать `frontend/` и `POST /api/ai/analyze` с одного origin либо настроить reverse proxy для `/api`.
2. Фронт уже читает `../graph.json`, как финальный Muha. Запуск: `python -m moneygraph --data data --out artifacts --serve`, затем `http://127.0.0.1:8765/frontend/`. GID передавать строками: это длинные int64. Все ресурсы льва включены в четыре разрешённых файла, API не добавлен.
3. Реализовать запросы и ответы чата по [AI_CONTRACT.md](AI_CONTRACT.md). Схема `answer` — [frontend/agent-answer.schema.json](frontend/agent-answer.schema.json).
4. Ключ и настройки модели хранить только на сервере, через окружение. Не коммитить `.env` и не передавать ключ в браузер.
5. Сверять SHA-256 точных байтов `graph.json`; историю привязывать к выбранному GID и версии графа. Повтор одного `request_id` не должен запускать второй платный вызов.

## Что уже делает фронт

- Открытие чата, выбор клиента и кнопки-подсказки не вызывают модель автоматически.
- Запрос содержит вопрос, `node_gid`, `dataset_sha256`, `request_id`, `conversation_id` и `schema_version: trace-ai.v1`.
- Ответ разделяется на факты, гипотезы, ограничения и следующие проверки; ссылки на GID открывают карточки.
- Минус / лев / Escape сворачивают окно без отмены запроса. «Остановить», смена клиента и замена графа прерывают ожидание. История разных клиентов не смешивается.
- Нет API — показана явная ошибка, без демо-ответов. Обычный `python -m http.server` не обслуживает этот POST.

## Быстрая проверка

```sh
node --test frontend/data.test.cjs frontend/agent.test.cjs frontend/agent-ui.test.cjs
```

После подключения сервера: выбрать клиента → «Разобрать с ИИ» → «Разобрать этот узел» → задать уточнение → проверить переход к GID из ответа. Полный чеклист и HTTP-коды ошибок находятся в `AI_CONTRACT.md`.

`data/`, `out/`, `.env` и материалы организаторов исключены из Git. Данные нужно положить локально; существующие `pipeline.py` и `requirements.txt` входят в проект.
