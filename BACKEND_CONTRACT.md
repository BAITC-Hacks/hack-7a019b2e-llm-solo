# Контракт фронтенда TRACE и локального бэкенда

Основа интерфейса и первоначальный контракт получены из `origin/Zhans`, коммит `bdbbb65`.

> **Go-слой отменён решением команды.** Сервер приложений не создаётся. Контракт интеграции:
> Python выполняет анализ и записывает `artifacts/graph.json`, браузер получает его локальным
> импортом и отображает результаты. Формулы ролей в JavaScript не дублируются. Упоминания
> Go ниже сохранены как история согласования и к реализации не относятся.

## Как подключить результат анализа

`frontend/app.js`, функция `loadDefault()`, читает **GET /api/graph** с того же origin. Ответ содержит весь граф. Ошибка API показывается пользователю; старые файлы автоматически не подставляются.

Python экспортирует `artifacts/graph.json` для локального импорта и `artifacts/api-snapshot.json` для Go. Не извлекать метрики из HTML и не запускать `starter.py` для итоговой аналитики: основной пакет — `python -m moneygraph --data data --out artifacts`.

Кнопка «Импорт данных» читает локальный JSON без отправки на сервер. После импорта frontend не запрашивает операции у API: они могут относиться к другому набору. Исходные данные и рассчитанные JSON исключены из Git. Команды общего запуска — в README.

## Формат ответа

Объект содержит непустой массив `nodes`, массив `edges` и `snapshot_id` для контроля версии данных. Ниже — синтетический пример полей узлов и рёбер, не результат анализа датасета.

```json
{
  "snapshot_id": "synthetic-example",
  "nodes": [
    {
      "gid": "100000000000000001",
      "role": "distributor",
      "role_score": 0.75,
      "cluster_id": 0,
      "priority_score": 0.65,
      "evidence": "Пример: исходящий оборот 90000 KZT, 3 перевода на 1 контрагента.",
      "depth": 0,
      "is_seed": true,
      "in_kzt": 0,
      "out_kzt": 90000,
      "truncated_by_depth": false
    },
    {
      "gid": "100000000000000002",
      "role": "terminal",
      "role_score": 0.7,
      "cluster_id": 0,
      "priority_score": 0.3,
      "evidence": "Пример: входящий оборот 90000 KZT, исходящих переводов в выборке нет.",
      "depth": 1,
      "is_seed": false,
      "in_kzt": 90000,
      "out_kzt": 0,
      "truncated_by_depth": false
    }
  ],
  "edges": [
    {
      "src": "100000000000000001",
      "dst": "100000000000000002",
      "sum_kzt": 90000,
      "n_tx": 3
    }
  ]
}
```

Пример иллюстрирует поля, а не критерии присвоения ролей.

## Значение полей и ограничения

| Поле | Требование |
| --- | --- |
| gid, src, dst | Строки десятичных цифр. Не JavaScript Number: длинные int64 округляются. |
| role | coordinator, consolidator, distributor, transit, terminal или peripheral. |
| role_score, priority_score | Конечные числа от 0 до 1. Интерфейс показывает шкалу 0–100. |
| cluster_id | Целочисленный идентификатор группы: число или строка. |
| evidence | Текстовое численное обоснование роли/приоритета. HTML не нужен. |
| depth | Неотрицательное целое: глубина обхода из исходных данных, seed имеет глубину 0. Не должность и не финансовая иерархия. |
| is_seed | Boolean true/false. |
| in_kzt, out_kzt | Неотрицательные численные обороты в тенге внутри наблюдаемого графа. |
| truncated_by_depth | Boolean: есть ограничение видимости на границе обхода. |
| sum_kzt | Неотрицательная суммарная величина переводов по направленной паре. |
| n_tx | Неотрицательное целое количество переводов этой пары. |

Передавайте все перечисленные поля. Для некоторых отсутствующих численных полей текущий frontend использует 0, но это совместимость загрузчика, а не замена расчёту метрик.

- Каждый gid уникален; обе вершины каждого ребра присутствуют в nodes.
- Передавайте всю сеть, не только top-20. Ограничение числа видимых узлов делает frontend.
- Одна запись edges на направленную пару src → dst; обратное направление — отдельная запись.
- in_deg и out_deg frontend вычисляет по уникальным контрагентам без самопереводов. Роли и скоринг он не рассчитывает.
- На depth >= 4 без исходящих frontend дополнительно отмечает границу данных. Не делайте из отсутствия исходящих автоматический вывод о конечном получателе.
- Для seed-клиентов интерфейс предупреждает, что входящие потоки могут быть неполными.
- Не передавайте NaN/Infinity, отрицательные суммы и ссылки на неизвестные gid.

## Что использует интерфейс

- Обзор и граф: nodes + edges; точный поиск любого gid показывает всех прямых соседей.
- Очередь проверки: priority_score; экспорт CSV использует evidence как why.
- Кластеры: cluster_id; внутренний оборот считается только по рёбрам с обоими концами в группе.
- Карточка клиента: роль, скоры, evidence, обороты, все входящие/исходящие связи и постраничные операции для набора из API.
- Самый приоритетный клиент текущей выборки попадает в заметку «Начальная точка».

CSV-файлы сдачи (nodes_roles.csv, clusters.csv, top_nodes.csv) — отдельные результаты пайплайна. Браузер не читает их вместо graph.json.

## Численные основания роли

Узлы могут содержать дополнительные поля Python: `in_tx`, `out_tx`, `pass_through` (число или null), `seed_reach`, `betweenness`, `other_clusters`, `component_id`, `active_days`, `matched_roles`, `priority_parts`, `peripheral_reason`, `peripheral_reason_text`. Метрики отсутствующего поля не заменяются нулём. `matched_roles` содержит только исходные значения enum; `priority_parts` — численные взвешенные вклады в [0,1].

Для временного сопоставления передаются `temporal_window_days`, `temporal_matched_kzt`, `temporal_in_fraction`, `temporal_out_fraction`, `temporal_strict_matched_kzt`, `temporal_strict_in_fraction`, `temporal_strict_out_fraction`, `temporal_same_day_matched_kzt`. Доли в [0,1]. Строгий вариант исключает совпадения внутри дня; основной вариант допускает их, но не устанавливает реальную очерёдность. Месячные суммы включают самопереводы, сопоставление движения между людьми исключает их. На официальном наборе самопереводов нет.

`limitations` и `next_query`, если переданы, — текст. Карточка сохраняет ограничения и показывает численные основания без генеративного объяснения. Старый `temporal_2d` читается для совместимости, но не заменяет обе новые доли.

## API для карточки и следующих экранов

| GET | Назначение |
| --- | --- |
| `/api/graph` | Полные nodes + edges для TRACE, snapshot_id |
| `/api/health` | Готовность снимка |
| `/api/summary` | Параметры и агрегаты набора |
| `/api/top?limit=20` | Начало рассчитанного рейтинга |
| `/api/nodes/{gid}` | Метрики и роль клиента |
| `/api/nodes/{gid}/neighbors?direction=both&hops=1` | Окружение с направленными рёбрами |
| `/api/nodes/{gid}/transactions?offset=0&limit=100` | Страница отдельных операций |
| `/api/clusters` | Список кластеров |
| `/api/clusters/{cluster_id}` | Узлы и связи кластера |

Коллекции: `{ "items": [...], "total": 123 }`. Операция: `{ "row_id": 1, "src": "...", "dst": "...", "date": "2026-07-01", "sum_kzt": 5000.01, "cents": 500001 }`. `row_id` — номер записи в канонически отсортированном экспорте текущего снимка, не исходный банковский ID. Даты без времени суток, деньги точно до сотых KZT, одинаковые операции остаются отдельными строками.

`limit` операций — 1–500, `offset` ≥0; TRACE запрашивает 100. Порядок канонический: дата, затем `row_id`. Ответы содержат `X-Snapshot-ID`, совпадающий с `snapshot_id` графа. При несовпадении frontend требует обновить граф. Подграф имеет `{ "nodes": [...], "edges": [...], "truncated": false }`; `truncated` означает лимит ответа и не равен `truncated_by_depth` узла.

Изолят остаётся известным клиентом и получает пустую коллекцию с HTTP 200. Неизвестный gid — 404, неправильные параметры — 400. Ошибки: `{ "error": { "code": "node_not_found", "message": "Клиент не найден" } }`. Сервер привязан к `127.0.0.1`; браузер не обращается к CDN или внешним API.

## Проверка совместимости

Из корня репозитория:

```sh
node --test frontend/data.test.cjs frontend/backend.test.cjs
python -m http.server 8000 --bind 127.0.0.1
```

Откройте http://127.0.0.1:8000/frontend/ при статической раздаче из корня (или `frontend/index.html` как файл) и импортируйте `artifacts/graph.json`. Проверьте точный gid, карточку, доли времени, суммы с сотыми, окружение, фильтры и экспорт.

Важно: загрузку ответа сохраняйте через response.text() → MoneyGraph.parse() → MoneyGraph.normalize(). Не заменяйте её на response.json(): текущий пайплайн может выдавать int64 без кавычек. Новый API должен сразу возвращать идентификаторы строками.
