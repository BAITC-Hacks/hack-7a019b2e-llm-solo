# Контракт Python → JSON → TRACE

Основа интерфейса и первоначальный контракт получены из `origin/Zhans`, коммит `bdbbb65`. Итоговая интеграция использует **Python и статический JSON**. Python рассчитывает роли, кластеры, приоритеты и метрики; JavaScript отображает их. Отдельный сервис и динамический API не требуются. Формулы ролей в браузере не дублируются.

## Запуск и загрузка

Из корня репозитория:

```powershell
.\.venv\Scripts\python.exe -m moneygraph --data data --out artifacts --serve
```

Откройте `http://127.0.0.1:8765/frontend/`. Python публикует `artifacts/graph.json` и копирует статические файлы интерфейса в `artifacts/frontend/`. Функция `loadDefault()` читает `../graph.json` один раз. При ошибке показываются повторная загрузка и импорт; старый файл с другого пути автоматически не подставляется.

«Импорт данных» читает выбранный `graph.json` прямо в браузере. Можно открыть `artifacts/frontend/index.html` без сервера и импортировать JSON вручную. Граф, отдельные операции и страницы карточки используют один загруженный снимок. Клиент не отправляет данные наружу и не делает запросов при открытии карточек.

Исходные данные, рассчитанный JSON и HTML не входят в Git. Все эти результаты содержат связи клиентов и требуют такого же режима доступа, как исходный набор.

## Формат снимка

```text
{
  schema_version: 1,
  snapshot_id: string,
  nodes: Node[],
  edges: Edge[],
  transactions: Transaction[],
  clusters: Cluster[],
  top: TopNode[],
  summary: object,
  config: object,
  output_sha256: object
}
```

`snapshot_id` обозначает входные файлы, конфигурацию, версию правил и хеши обязательных CSV данного расчёта. Это контроль воспроизводимости, не электронная подпись. Старый минимальный формат `{nodes, edges}` остаётся доступным для импорта; карточка явно сообщает об отсутствии отдельных операций. Не подставлять пустой `transactions` вместо отсутствующего поля.

Для `schema_version: 1` браузер требует операции и идентификатор снимка, сверяет их суммы в сотых и количество с каждой направленной парой `edges`, а обороты/количества каждого узла — с рёбрами. Повтор пары и неизвестная версия схемы отклоняются. Это защищает от частично смешанных или повреждённых экспортов.

| Поле узла | Требование |
| --- | --- |
| gid | Строка десятичных цифр; все узлы исходного файла, включая изоляты |
| role | coordinator, consolidator, distributor, transit, terminal или peripheral |
| role_score, priority_score | Конечные числа в [0,1]; не вероятность виновности |
| cluster_id | Целочисленный идентификатор группы |
| evidence | Численное текстовое обоснование, не пустое, максимум 200 символов в экспорте Python |
| depth | Глубина обхода из данных, не должность и не иерархия |
| is_seed | Boolean; начало обхода, не установленный организатор |
| in_kzt, out_kzt | Наблюдаемые обороты с точностью до сотых KZT, не баланс счёта |
| truncated_by_depth | Boolean; обрыв видимости на границе обхода |

Ребро: `{src: string, dst: string, sum_kzt: number, cents: integer, n_tx: integer, depth: integer}`. Одна запись на направленную пару; обе вершины присутствуют в `nodes`. Обратное направление — отдельная запись. `sum_kzt = cents / 100`; не складывать обороты рёбер и операций как разные деньги.

GID больше безопасного диапазона JavaScript Number. Новый экспорт передаёт `gid`, `src`, `dst` и массивы GID строками. Загрузка сохраняет цепочку `response.text()` → `MoneyGraph.parse()` → `MoneyGraph.normalize()`; lossless-парсер поддерживает старый числовой JSON без округления длинных целых. Не заменять его на `response.json()`.

## Численные основания роли

Узлы дополнительно содержат `in_tx`, `out_tx`, `pass_through` (число или null), `seed_reach`, `betweenness`, `other_clusters`, `component_id`, `active_days`, `matched_roles`, `priority_parts`, `peripheral_reason`, `peripheral_reason_text`. Отсутствующая метрика отличается от нуля. `matched_roles` содержит значения исходного enum; `priority_parts` — численные взвешенные вклады в [0,1].

Временные поля: `temporal_window_days`, `temporal_matched_kzt`, `temporal_in_fraction`, `temporal_out_fraction`, `temporal_strict_matched_kzt`, `temporal_strict_in_fraction`, `temporal_strict_out_fraction`, `temporal_same_day_matched_kzt`. Доли лежат в [0,1]. `external_in_kzt` и `external_out_kzt` — знаменатели долей без самопереводов. Основные месячные `in_kzt/out_kzt` самопереводы включают.

Сопоставление допускает несколько входов и выходов, не расходует один входящий объём повторно. Основной вариант допускает совпадения внутри дня, строгий их исключает. Очерёдность внутри дня и прохождение именно тех же денег данными не установлены. Старый `temporal_2d` сохраняется для совместимости, но не заменяет обе новые доли.

`limitations` и `next_query`, если переданы, — текст. Фронтенд не генерирует объяснения через LLM. Подписи ролей обозначают гипотезы: «Кандидат на транзит», «Структурный посредник», «Роль не установлена». Исходный enum в данных и CSV сохраняется.

## Отдельные операции

```json
{"row_id":0,"src":"100000000000000001","dst":"100000000000000002","date":"2026-07-01","sum_kzt":5000.01,"cents":500001}
```

Это синтетический пример. `row_id` — номер записи в канонически отсортированном экспорте текущего снимка, не банковский ID. Совпадающие операции с разными `row_id` сохраняются. Повтор самого `row_id`, неизвестный конец перевода, некорректная дата и несогласованные деньги отклоняются при загрузке.

Даты передаются как `YYYY-MM-DD`: без вымышленного времени суток и пересчёта часового пояса. Все операции загружаются вместе с JSON. Браузер строит индексы по отправителю и получателю; самоперевод попадает в индекс клиента один раз. Карточка показывает страницы по 100 операций, упорядоченных по дате и `row_id`, без дополнительных сетевых запросов.

## Выгрузки и проверка

`nodes_roles.csv`, `clusters.csv` и `top_nodes.csv` — обязательные отдельные результаты Python. Их схемы не меняются ради интерфейса. Браузер экспортирует текущий отфильтрованный список с колонками `rank,gid,role,priority_score,why`.

```sh
node --test frontend/data.test.cjs frontend/backend.test.cjs
```

Проверяются точность GID, нулевые метрики, денежные сотые, даты, сохранение одинаковых операций, локальные индексы и страницы, повреждённый JSON, отсутствие скрытой подмены файла и гонки чтения двух файлов. Исходные `frontend/data.test.cjs` сохранены. Дизайн: `frontend/DESIGN.md`; запуск: основной README.
