# Аналитика: правила, результаты и проверка

## Запуск

```powershell
python -m pip install -r starter/requirements.txt
python starter/starter.py --data data --out out
python -m unittest discover -s tests -v
```

Запускать из корня с выбранным рабочим Python. На проверенной машине локальная `.venv` ссылается на недоступный Python312. Проверка выполнена в доступном bundled Python с pandas 3.0.1, numpy 2.3.5, networkx 3.7, fastparquet 2026.5.0. Это не подтверждение чистой установки на другом компьютере. Основной движок Parquet — pyarrow, резервный fastparquet теперь объявлен в requirements.

## Этапы

1. Проверка схем, пропусков, целочисленных ID, уникальности узлов/пар, наличия клиентов, сумм и количества переводов. Допуск денежных агрегатов — 0,01 ₸ без относительного допуска. Повторяющиеся транзакции сохраняются.
2. Направленный граф со всеми узлами, включая изолированные. Перед расчётом узлы и рёбра сортируются для стабильности независимо от порядка строк исходника.
3. Признаки: количество отправителей/получателей, суммы, количество операций, PageRank, HITS, достижимость от seed, отношение исходящего/входящего оборота, FIFO-сопоставление за 0–2 дня.
4. Louvain на неориентированной проекции с суммированием встречных весов, seed=42, resolution=1. Изолированный граф обрабатывается отдельными кластерами. Внутренний оборот считается по направленным исходным рёбрам один раз.
5. Основная роль, оценка правила, независимый рейтинг и объяснения.
6. Три обязательных CSV, дополнительная таблица признаков, JSON для бэкенда и HTML.

PageRank использует суммы как веса и alpha=0.85. В HITS вес — квадратный корень суммы, уменьшающий влияние очень крупных переводов. Лимиты итераций — 250 и 200; допуск 1e-10. Эти метрики описывают структуру, а не виновность; достижение лимита итераций само по себе не доказывает сходимость.

## Роли и приоритет правил

Правила применяются сверху вниз, первая подходящая роль становится основной. Несколько моделей поведения могут сосуществовать; текущая модель не выводит несколько ролей одновременно. Пороги являются выбором команды, а не размеченными ответами организаторов.

| Роль | Условие |
| --- | --- |
| coordinator | Не seed, пути от ≥2 разных seed, ≥2 отправителей и ≥2 получателей. Гипотеза о связующем узле, не доказанное руководство |
| consolidator | Не seed, ≥3 отправителей, ≥1 получателя. Сбор с последующей отправкой |
| distributor | ≥5 получателей |
| transit | Не seed, есть вход/выход; out/in от 0.70 до 1.30 включительно ИЛИ FIFO-доля исходящей суммы ≥0.35 |
| terminal | Не seed, есть вход, нет выхода, узел не обрезан на depth=4 |
| peripheral | Другие случаи, включая недостаток наблюдений и изолированные узлы |

Ограничение: сборщик, который только накапливает деньги без исходящих, по текущему порядку получает terminal (или peripheral на границе). Интерпретировать роли следует именно в рамках этих операционных определений.

Для силы правила используются фиксированные эвристики (d_in/d_out — числа контрагентов, s — число достижимых seed):

- coordinator: min(0.96, 0.62 + 0.08×min(s,3) + 0.04×min(d_in,5)).
- consolidator: min(0.94, 0.60 + 0.05×min(d_in−3,5) + 0.04×min(d_out,3)).
- distributor: min(0.94, 0.60 + 0.04×min(d_out−4,7) + 0.04×min(d_in,4)).
- transit: min(0.92, 0.52 + 0.22×(1−min(abs(out/in−1),1)) + 0.22×FIFO-доля).
- terminal: 0.72; peripheral: 0.48 на границе, иначе 0.42.

Это не вероятности и не эмпирически откалиброванная уверенность. В частности, фиксированная оценка terminal не устраняет неполноту наблюдений.

## Формула приоритета

Каждый признак преобразуется в относительный ранг: `(средний ранг − 1) / число узлов`; для постоянного признака результат 0. Равные значения получают одинаковый ранг.

| Признак | Вес |
| --- | --- |
| in_deg | 0.18 |
| out_deg | 0.18 |
| authority_score | 0.20 |
| hub_score | 0.16 |
| pagerank | 0.16 |
| seed_sources | 0.12 |

Итог — сумма взвешенных рангов × priority_factor: 0 для изолированных узлов, 0.75 для обрезанной границы, иначе 1. Все взвешенные ранги доступны как contribution_* в экспорте. Снижение на границе — эвристика неполноты наблюдений, не доказательство меньшего риска.

В why выводятся три наибольших вклада, их исходные значения, множитель и итог. Полные шесть вкладов сохраняются отдельно. Приоритет округляется до четырёх знаков, равенства в топе разрешаются по gid. Большой оборот не является самостоятельным слагаемым; суммы влияют через взвешенные графовые метрики.

## Время и неполные данные

FIFO сопоставляет исходящие с неиспользованными поступлениями за последние два дня. Одно поступление не используется повторно. Поступления одного дня рассматриваются раньше отправок этого дня — это допущение, поскольку точного времени нет. Совпадение сумм не доказывает передачу тех же денег. Переводы раньше поступления по дате или позже двух дней не сопоставляются.

У seed входящие неполны; роль transit и другие правила, требующие надёжной интерпретации входа, для них исключены. Клиенты depth=4 без выхода не объявляются terminal. Сеть ограничена отбором переводов и четырьмя переходами. Нет ground truth: качество выявления преступлений и accuracy не измерялись.

## Файлы для бэкенда

- nodes_roles.csv, clusters.csv, top_nodes.csv — обязательные контракты сохранены.
- node_features.csv — все числовые признаки, contribution_* и priority_factor; одна строка на клиента.
- analysis.json — schema_version=1, nodes с ролями и признаками, edges, limitations. gid/src/dst — строки; неопределённое отношение оборотов — null, не NaN. Денежные суммы не округляются до целых тенге.
- index.html — автономная страница; идентификаторы в её данных также строки.

Бэкенду не нужно извлекать данные из HTML или повторять формулу рейтинга. Он может использовать analysis.json и clusters.csv/top_nodes.csv. Сведения о новом экспорте дополняют ранее написанный BACKEND_HANDOFF.md.

## Масштабирование

Для миллиона узлов использовать компактные списки смежности или CSR/CSC, пакетную агрегацию, ограниченные подграфы для браузера. Отдельно профилировать многократную достижимость от seed и выборку рёбер для каждого кластера. Не обещать масштабирование только за счёт смены языка; текущая версия проверена на выданном наборе.
