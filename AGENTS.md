# Правила работы с «Графом денег»

## Решения команды — не пересматривать без явного указания

- **Стек окончательный: Python + pandas/PyArrow/NetworkX, автономный HTML и JavaScript.**
  Других языков и сетевых сервисов в решении нет. Сервер приложений не нужен: интерфейс
  читает `artifacts/graph.json` из локального файла, а `--serve` раздаёт готовые файлы.
  Не добавлять `backend/`, `scripts/run-backend.py`, npm-скрипты `start:api` и `test:backend` —
  они уже удалялись; при необходимости вернуть сначала спроси команду.
- **LLM в продукте не используется.** Предметное ядро остаётся офлайн: ни одного сетевого
  вызова, ключ не требуется. `src/` — прежняя отдельная заготовка, графовые роли не определяет.

## Контекст и команды

- Основной продукт — Python 3.11/3.12 пакет moneygraph: три Parquet → объяснимые роли/кластеры/приоритеты → три CSV и автономный HTML.
- Node.js src/ — отдельный прежний LLM-каркас. Не использовать greeting/help/unknown в предметном графовом контракте.
- Перед изменениями прочитай README.md, QA-REPORT.md (актуальный список дефектов от QA) и соответствующие файлы src/ и test/.
- Графовые проверки: `.venv/Scripts/python.exe -m unittest discover -s tests -v` (Windows); `.venv/bin/python` на Unix.
- Проверки Node: `npm test` (или `node --test`). Не менять test/qa-*.test.js и не скрывать падающие тесты; см. docs/QA-RESOLUTION.md.
- Основной запуск: `.venv/Scripts/python.exe -m moneygraph --data data --out artifacts --serve` либо `npm start`.
- Прежнее LLM-демо: `npm run llm:demo -- --offline "Привет"`.

## Инварианты предметного решения

- Опирайся на ТЗ, config/roles.json и реальные схемы, а не на заранее выбранные gid. Не хардкодь роли/кластеры/топ.
- Сохраняй ВСЕ узлы из nodes.parquet, включая изоляты. gid — int64 в Python/CSV и строка в браузере, никогда float.
- edges и transactions описывают одни переводы: сверяй суммы и количество, не складывай обороты двух файлов.
- Суммы — целые сотые KZT после проверки точности; не вычисляй полный баланс по неполному графу.
- depth=4 без исходящих — обрыв наблюдения, не terminal. Seed с неполным входом не классифицируется по O/I как удерживающий/транзитный.
- Роль, role_score и priority_score — объяснимая гипотеза, не вероятность преступления. Не добавляй придуманные персональные атрибуты.
- Обязательные CSV-поля сохраняй; evidence непустой, ≤200 символов. Top ≥20, если в наборе достаточно узлов.
- Детерминированные порядок узлов, random seed и разрешение связок. При изменении правил обновляй конфигурацию, README и предметные тесты.
- Основной сценарий работает без API, CDN и GPU. UI не отправляет данные наружу; локальный сервер слушает только 127.0.0.1.
- data/, artifacts/, Parquet и ключи не коммитить. HTML тоже содержит исходные связи и требует того же режима доступа.
- Проверяй сквозной запуск на официальном наборе, когда он есть. Без него не заявляй проверенными 2248 строк и время расчёта.

## Границы модулей

- `validator.js`: контракт ответа и проверка входа. Меняя контракт, синхронно обновляй schema, валидатор, правила, тесты и пример README.
- `openai-client.js`: только HTTP/OpenAI, строгая JSON Schema, ограничение времени и объёма ответа. Не отключай таймаут и не добавляй бесконечные повторы.
- `rules.js`: детерминированный fallback, без сети и побочных эффектов.
- `app.js`: валидация → LLM → fallback → память. Пустой ввод отклоняется до сетевых запросов и записи.
- `memory.js`: версия формата, проверка загруженных данных, резервная копия повреждённого файла и атомарная замена через временный файл в той же папке.
- `cli.js`: аргументы, окружение, JSON в stdout; диагностика только в stderr.

## Инварианты и качество

- Считай ответы LLM и содержимое памяти недоверенными. Проверяй типы, обязательные поля, enum и неизвестные поля ответа.
- Ошибка API, отказ модели, обрыв или мусорный ответ должны давать валидный fallback с причиной.
- Не затирай повреждённую память без резервной копии. Ошибка сохранения не должна терять готовый ответ.
- Тесты должны работать без ключа и сети: подменяй fetch/client, используй отдельные временные каталоги.
- Для исправленного сбоя добавляй регрессионный тест. Выполняй проверки перед завершением и честно указывай, если что-то не запускалось.
- Не добавляй ключи, .env, пользовательскую память или полные ответы HTTP-ошибок в Git и логи.
- Не делай реальные платные API-вызовы в тестах. Не добавляй зависимости без конкретной необходимости.
- Сохраняй пользовательские изменения. Не выполняй reset/clean и не меняй несвязанные файлы.
- Обновляй README при изменении команд, настроек, поведения и ограничений.

Эти правила написаны для данного репозитория; это не копия внутренних правил команды genZ.
